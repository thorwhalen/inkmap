inkmap.locate

Locators: finding where a model sits in an image.

A locator is a plain function (bgr, gray) -> list[Placement], so registering your own needs no subclassing:

from inkmap import locate

locate.LOCATORS[“mine”] = my_locator inkmap.find_all(photo, locators=[“mine”, “qr_zxing”])

For the many cases where the mark cannot be auto-detected – a letter, a logo, a shape with no decoder in the world – place() is the universal entry point: you supply the model and where its corners are, and the rest of the package proceeds identically. That is the seam that makes this work for “anything the user provides a model for”.

inkmap.locate.LOCATORS: dict[str, Callable[[ndarray, ndarray], list[Placement]]] = {'barcode_zxing': <function locate_barcode_zxing>, 'qr_aruco': <function locate_qr_aruco>, 'qr_opencv': <function locate_qr_opencv>, 'qr_zxing': <function locate_qr_zxing>}

LOCATORS["mine"] = my_locator.

Type:

Registry of locator strategies. Add your own

inkmap.locate.locate(bgr: ndarray, gray: ndarray, *, locators: Sequence[str | Callable[[ndarray, ndarray], list[Placement]]] = ('qr_zxing', 'qr_aruco', 'qr_opencv', 'barcode_zxing'), first_hit: bool = False) → list[Placement][source]

Run locator strategies and merge their results, de-duplicating by position.

Strategies are tried in order. With first_hit=True the cascade stops at the first strategy that finds anything – cheaper, and usually right when you know there is one mark. Otherwise every strategy runs and results merge, which is what earns the recall when an image holds several marks that no single detector finds all of.

inkmap.locate.locate_barcode_zxing(bgr: ndarray, gray: ndarray) → list[Placement][source]

Locate linear barcodes with zxing-cpp and model their bar pattern.

inkmap.locate.locate_qr_aruco(bgr: ndarray, gray: ndarray) → list[Placement][source]

OpenCV’s QRCodeDetectorAruco – finds the finder patterns as Aruco-like markers. Notably more robust than the classic detector on real photographs.

inkmap.locate.locate_qr_opencv(bgr: ndarray, gray: ndarray) → list[Placement][source]

OpenCV’s classic QRCodeDetector. Corners are inclusive pixel indices.

inkmap.locate.locate_qr_zxing(bgr: ndarray, gray: ndarray) → list[Placement][source]

zxing-cpp. Highest recall of the three, and its corners are the continuous outer boundary (spanning exactly N * scale), not inclusive pixel indices.

inkmap.locate.place(model: Model, quad, *, inclusive_pixel_corners: bool = False, locator: str = 'manual', **metadata) → Placement[source]

Place a model at a known quadrilateral – the universal escape hatch.

quad is four (x, y) image points in the model’s own corner order: the point corresponding to model-space (0, 0) first, then clockwise. Order matters and is not inferred: sorting corners by image position silently mislabels them once the mark is rotated past 45 degrees.

Use this for anything without a decoder – printed letters, logos, engraved marks – or when you already know where the mark is and only want the coverage machinery.
